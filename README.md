# VeriSearch

**RL-trained retrieval reasoner with a faithfulness reward.**

A small LLM trained with GRPO to interleave reasoning and retrieval: it decides *when* to
search, *what* to search for, and *when it has enough evidence* to answer. Rewarded on
verifiable correctness, citation faithfulness, and retrieval cost.

> Status: **P0 — setup.** No results yet. Every number in this README will carry a 95%
> bootstrap confidence interval and a W&B run link, or it will not be here.

The full brief and working agreement is [PROJECT.md](PROJECT.md).

## The idea in 60 seconds

Ask *"Which director of the 1999 film that won Best Picture was born in Australia?"*

Normal RAG searches once with the original question and answers. That fails twice over.
It needs two hops — find the film, *then* find the director's birthplace — and the second
query cannot be written until the first one returns. And when the retrieved passages come
back weak, the model fills the gap with a confident guess that no document supports.

VeriSearch trains the loop instead of scripting it:

```
question → think → search → read → think → search → read → answer
```

The model chooses how many loops. The reward has three terms pulling against each other:

| Term | What it measures | Weight |
|---|---|---|
| correctness | token F1 vs gold answer, plus EM bonus | `w_c = 1.0` |
| faithfulness | fraction of atomic claims entailed by *retrieved* passages | `w_a = 0.5` |
| retrieval cost | searches / `SEARCH_BUDGET`, subtracted | `λ` swept |

Faithfulness is the anti-hallucination lever and the part most work skips. Retrieval cost
is the dial: turn it up and the model searches less. Four models trained at four λ values
give an accuracy-vs-retrieval frontier — *how much accuracy does one more search buy?*

## Quickstart

```bash
uv venv --python 3.11
uv pip install -e ".[dev]"
```

Check your machine:

```bash
python scripts/00_setup_check.py
```

Run the same gates Jenkins runs:

```bash
uv run ruff check . && uv run ruff format --check . && uv run mypy --strict verisearch/ && uv run pytest
```

Extras are split so the PR pipeline stays CPU-only and fast:

| Extra | Install for | Who |
|---|---|---|
| `[dev]` | lint, typecheck, test — everything CI runs on a PR | both |
| `[retrieval]` | building the FAISS index, embedding, NLI scorer | Ayesha |
| `[train]` | vLLM rollouts, LoRA, GRPO | Dhrubo, GPU box only |

`uv.lock` is the real pin. Commit it; both machines install from it.

### What this means

Three findings, in priority order.

**1. GPU is not usable right now.** `nvidia-smi` cannot get a device handle — the driver
has lost the card. Reboot and re-run the check. Until it reports a name and VRAM figure,
the training plan has no confirmed hardware. VRAM decides the model path:

| VRAM | Viable |
|---|---|
| ≥ 16 GB | 1.5B and 3B both, per PROJECT.md section 5 |
| 8–16 GB | 1.5B only; 3B needs 4-bit NF4 or a smaller group |
| < 8 GB | GRPO at group 8 will OOM — rent a GPU |

**2. Dhrubo's hardware is unknown.** He cannot run rollouts without a GPU, and P3 assumes
he can. Confirm before P1 closes. If he has none, the plan changes: he develops against a
fake retriever and CPU-tiny models, and training runs on Ayesha's box or rented GPU.

**3. 84 GB free disk is tight for a full Wikipedia index.** Rough estimate for a full
paragraph dump: ~20M passages × 384 dims × 4 bytes ≈ 32 GB of vectors, plus raw text, plus
HNSW graph overhead, plus checkpoints. Two mitigations, pick one at P1:

- Use the HotpotQA Wikipedia **abstracts** dump (~5M paragraphs) instead of the full dump.
  Standard for multi-hop QA work, roughly 8 GB of vectors, and it keeps the corpus aligned
  with the training data. Recommended.
- Free disk or attach an external drive before building the index.

Re-run the check after the reboot and update this section. **The RESULT line must read
PASS before P1 starts.**

## Engineering standards

Enforced in CI. A PR violating any of these does not merge.

- `mypy --strict` on the whole package. No bare `Any`.
- `from __future__ import annotations` in every module — enforced by ruff `I002`.
- Data crossing a module boundary is a Pydantic v2 model or a frozen dataclass, never a
  raw dict.
- Reward functions are pure: no I/O, no globals, deterministic.
- Coverage floor 80%. Tightens to `rewards/`, `env/`, `eval/metrics/` at P2.
- **`tests/test_masking.py` is mandatory and blocking** from P3. Injected `<info>` tokens
  were not generated by the policy and must carry zero loss weight. Unmasked, the model
  learns to predict its own retrieval results — invisible in training curves, and it
  poisons every number downstream.

## Pipeline

| Stage | Command | Blocking |
|---|---|---|
| `lint` | `ruff check`, `ruff format --check` | yes |
| `typecheck` | `mypy --strict verisearch/` | yes |
| `unit` | `pytest -m "not gpu and not integration"`, coverage 80% | yes |
| `integration` | 5-question end-to-end, fake retriever, CPU | yes |
| `smoke-train` | 5 GRPO steps on 1.5B, asserts loss finite | nightly, `main` |
| `eval-regression` | fixed 100-example eval, F1 must not drop > 2 pts | nightly, `main` |
| `artifact` | publish coverage + eval report | `main` only |

Red pipeline blocks review. A red `main` is the top priority for both people.

Nightly stages are guarded on `scripts/02_train.sh` and `scripts/03_eval.sh` existing, so
they skip cleanly until P3 lands them.
